### Reverse-revert rehearsal — DRY-RUN (not executed)

**Undoing slice E specifically** (the top of the stack; contiguous commits `cf865c5`→`7890139`→`dd7d2c6`,
with `dd7d2c6` = HEAD):

1. E is 3 commits with **no migration** (it reused the slice-B indexes), so reverting E never touches
   the DB schema — the cleanest possible rollback boundary.
2. Non-destructive path (correct once the branch/PRs are pushed & shared):
   `git revert --no-commit dd7d2c6 7890139 cf865c5` then a single
   `git commit -m "revert(reportes): undo slice E fiscal + DGII exporters"` — or three separate
   `git revert` commits to preserve work-unit granularity. Revert newest→oldest to respect intra-slice
   file dependencies (the `exportar.ts` dispatcher fiscal branch and `catalogo.ts`
   `REPORTES_FISCALES_SLICE_E` ids are added in `7890139`; the `domain/dgii/*` sources in `cf865c5`).
3. Effect of the revert: `/reportes` drops the five fiscal ids from `REPORTES_IMPLEMENTADOS` (selector
   shows "próximamente"), the `/reportes/exportar-txt` route and `exportar-fiscales`/`exportar` fiscal
   branch disappear, and the fiscal panels are gone — operational/financial/rentabilidade/dashboard
   (slices A–D) remain byte-intact.
4. Destructive alternative (valid ONLY while unpushed, as today): `git reset --hard 2648c19` (slice-D
   tip) drops all three E commits in one move. Not acceptable post-push/post-review.

**How the isolated migration commit (`13de13a`) enables clean reversion generally:** because the three
report indexes live in their own `chore(db)` commit with zero feature entanglement, any rollback of the
data layer is surgical — `git revert 13de13a` removes exactly the `@@index` decls + the `.sql`, and the
corresponding DB change is a plain `DROP INDEX` of the three additive indexes (no data migration, no
row rewrite, reversible by re-applying the same additive file via `prisma migrate`). Slices C/D/E depend
on those indexes only for *performance*, never for *correctness*, so reverting `13de13a` while keeping
later slices degrades query speed but does not break any report. Conversely, reverting slice B's feature
commits (`40e6fcc`, `a06298c`, `0add524`) leaves `13de13a` independently revertable — the two concerns
are decoupled by the isolation rule, which is exactly why the migration was committed alone.
