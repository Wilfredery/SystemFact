# Administración — activate and deactivate a branch (slice C of "branch moves + branch management")

Branch `feature/administracion-sucursales-activar` · target v0.34.0 · NO migration (`sucursal_update` is already admin-only since v0.33.0; the `activa` column and the `ACTUALIZAR` audit action exist). Slices A (user move, v0.32.0) and B (create/edit, v0.33.0) are shipped.

## Specs

- S1 Scope of THIS PR: one write on `SUCURSAL.activa`, Administrador only: **deactivate** and **reactivate** a branch of the session empresa, from Administración > Sucursales. NO delete (branches are never deleted: every document table references `sucursalId` with Restrict, `sucursal_delete` is bootstrap-only), NO change to slice A/B behaviour other than the locking of S5.
- S2 Authorization, same as slice B: `tieneRolPermitidoEnTx` with `ROLES_GESTION_SUCURSALES` inside `withTenantTransaction`, deny-by-default, `TEN_OPS_NO_AUTORIZADO`; thin adapters; no Prisma in `http/`; typed results with stable codes in `tenant/domain/errors.ts` only; no stack/Prisma error to the client.
- S3 Deactivation blockers, owner decision L2 ("All four (recommended)"): deactivation is REFUSED while the branch has any of (a) **active users** (`USUARIO.activo` and `sucursalId` = the branch; inactive users do not count), (b) **stock above zero** (`INVENTARIO.cantidad > 0` for the branch), (c) **open documents** (`VENTA` in BORRADOR and `COMPRA` in BORRADOR or PENDIENTE; fiscal documents FACTURA/NOTA_CREDITO/NOTA_DEBITO are never "open"), (d) **unpaid customer balances** (any confirmed sale of the branch whose derived balance is above zero, computed with the EXISTING canonical balance query, never a new formula, ADR-017: balances are derived, never stored). Each blocker has its own stable error code and the refusal carries the COUNT so the screen can say "3 usuarios activos, 12 productos con stock…" (all blockers are evaluated and reported together, not first-fail). All counts are SQL aggregates (no loops, no N+1) run in the SAME transaction as the lock of S5, under the company-wide branch widen (`conSucursalAmpliadaEnTx`-style: blank branch GUC for the reads only, empresa GUC never touched, restored in `finally`), because RLS pins branch-scoped tables to the session branch and would silently count zero for any other branch.
- S4 More refusals, owner defaults L3: the Administrador cannot deactivate **their own current branch** (the session branch) and the company's **last active branch** (the selector would be empty); both with their own stable code. Reactivation has NO conditions. A branch that is already in the requested state is an idempotent no-op: success, no write, no version bump, NO audit.
- S5 Concurrency (slice A review advisory + new race): (a) deactivate takes `SELECT ... FROM "SUCURSAL" WHERE id AND "empresaId" FOR UPDATE` BEFORE the counts and the version-checked `UPDATE`; (b) every path that PUTS a user in a branch takes `... FOR SHARE` on the destination `SUCURSAL` row inside its transaction instead of the plain read: the user move (`gestion-usuarios.ts`, currently `leerSucursalActivaEnTx`), the branch switch (`cambiarSucursalActiva`, `repo-sucursal.ts`), and user creation if the code has such a path (verify; seeds use the privileged role and are out of scope). Effect: a move in flight blocks the deactivation until it commits, which then counts the moved user and refuses; if the deactivation commits first, the move's locked read returns no active branch and it refuses (`TEN_SUCURSAL_NO_VALIDA`). `FOR UPDATE` needs `sucursal_update` (admin only), which already holds; `FOR SHARE` needs only SELECT.
- S6 Optimistic lock and audit: the write is `UPDATE ... WHERE id AND empresaId AND version` with `version + 1` (stale → the existing `TEN_CONCURRENCIA_CONFLICTO`, nothing changed), same savepoint/RLS-refusal mapping as slice B (`escribirGuardado`, RLS refusal → `TEN_OPS_NO_AUTORIZADO`). Exactly ONE audit row per real change: `ACCION_AUDITORIA.ACTUALIZAR`, `entidad: "Sucursal"`, before/after `{ activa }`, `sucursalId: null`, like the user activate/deactivate of v0.28.0. A refused or no-op call writes none.
- S7 Read side: the Sucursales list shown to the Administrador must include INACTIVE branches with their real `activa` flag (and `version`), replacing the hardcoded "Activa" badge; the branch SELECTOR, the "Mover de sucursal" dialog and the login count stay active-only. A new list read (or flag) for the admin tab; the existing active-only readers do not change behaviour.
- S8 UI (Administrador only, same gate as slice B): in the Sucursales table a **Desactivar/Activar** action per row with a confirmation dialog (names the branch; explicit confirm; buttons disabled while pending; definitive state shown only after the server confirms, then the list is re-read; a conflict reloads and never retries). A blocked deactivation shows ONE clear Spanish message listing every blocker with its count (e.g. "No se puede desactivar: 3 usuarios activos, 12 productos con existencias, 1 compra abierta, 2 clientes con saldo pendiente."), and the own-branch and last-branch refusals have their own messages; the action is disabled with an explanatory title on the session's own branch. Inactive rows show an "Inactiva" badge and keep "Editar". Screen state must be DERIVED from the server props (lesson of slice B: `useState(prop)` seeds once and went stale after a tab switch).
- S9 Tests: domain unit (pure decision: blockers, own branch, last branch, no-op); use-case unit; integration (real Postgres, `systemfact_app`): each blocker alone refuses with the right code and count, all together report all counts, deactivation OK when none, reactivation OK, own branch and last active branch refused, idempotent no-op writes nothing, stale version refused, Operador refused at the gate AND by the DB, cross-empresa branch → `TEN_SUCURSAL_NO_VALIDA`, counts see OTHER branches' rows (widen) and never another empresa's, the branch GUC restored after the call, and the RACES: a user move into branch X in flight vs deactivation of X (exactly one wins, and no active user ends on an inactive branch), and a branch switch likewise. RTL for the action, dialog, blocker message, own-branch disabling, inactive badge. e2e: the Administrador creates a throwaway branch (unique name, cleaned up by superuser SQL like slice B), deactivates it, sees "Inactiva" and that it vanished from the Mover dialog, reactivates it; a branch with an active user shows the blocker message; it must not skip and must not leave extra ACTIVE branches that break other specs.
- S10 Version bump 0.34.0 (feat → MINOR) in `app/package.json` + `.release-please-manifest.json` + `app/CHANGELOG.md` (UTF-8 without BOM) in the final patch commit; native review of the backend commit alone (risk + resilience: locking, widened reads) before the push; production deploy only with the owner's explicit approval. No migration, so the owner applies nothing.
