# Inventario — Historial de movimientos (read-only)

Branch `feature/inventario-historial` · target v0.30.0 (feat → MINOR) · issue-first PR gate. Owner choice (2026-11-14): "Movement history". The open product questions were delegated to the agent ("do whats the professional best practical, safe and security way"): answers recorded in S1-S4.

## Specs

- S1 Read-only sub-route `/inventario/movimientos` (server page + client island, same pattern as the stock list `InventarioScreen`), reached by a link from the stock list. NOT a menu entry. No write control anywhere. Columns: Fecha (America/Santo_Domingo, local date-time), Producto (codigo + nombre), Tipo (human label of the `TipoMovimiento` enum), Cantidad movida (signed), Cantidad anterior, Cantidad nueva, Usuario (nombre), Motivo. Filters: tipo de movimiento (enum), producto (text search over codigo/nombre), rango de fechas (Desde/Hasta, `YYYY-MM-DD` business days). Pagination 25 per page, max 100, "Página X de Y". Empty state when nothing matches. Never expose `idempotencyKey`, cost, or valuation.
- S2 Visibility (agent decision, least privilege): ONLY the Administrador (`ROLES_GESTION_INVENTARIO`; no literal role name written outside `inventario/http/shared.ts`). Reason: the history reveals who adjusted stock and why. Operador/Despachador get the access message with no data and no link. Widening later is one constant. Deny-by-default; server-enforced (the link visibility is UX only).
- S3 Scope (agent decision): the session BRANCH only (Administrador included, P6 pin). The query MUST filter `inventario.sucursalId = ctx.sucursalId` and `inventario.sucursal.empresaId = ctx.empresaId` (same `inventarioTenantWhere` idea as the stock list) in addition to RLS (`movinventario_isolation`, branch GUC pinned). The reader must NOT run inside any transaction that blanks `app.current_sucursal_id` (see `stockTotalEmpresaEnTx`). Company-wide history is out of scope.
- S4 Bounded by design (no index on `fecha` exists; measure before adding one, AGENTS Performance): the date range is MANDATORY with a default of the last 30 SD days and a maximum span of 90 days; an out-of-range or inverted range is a typed validation error with a stable code; `limit` default 25 / max 100; the page and the total use the SAME `where`; explicit `select` (nested producto codigo/nombre, usuario nombre), one `findMany` + one `count`, no N+1, no heavy include. Order `fecha desc, id desc`. Date window built with `caja/domain/zona.ts` (`ventanaDiaSD`, half-open `[inicio, fin)`), no manual hour arithmetic.
- S5 Layers per AGENTS: pure domain for range validation/defaulting and the tipo labels (no Prisma/Next), application use case `listarMovimientosInventario`, infrastructure repository function, thin Server Action `listarMovimientosInventarioAction` (validate with Zod, `getCurrentTenantContext`, `withTenantTransaction`, role check via `tieneRolPermitidoEnTx`, stable error codes from the inventario catalog only, no stack traces). No audit row per read (matches the stock list; documented).
- S6 Nothing else changes: no migration, no RLS change, no schema change, no change to any writer of `MovimientoInventario`, no change to the stock list behavior except the permission-gated link to the history.
- S7 Tests: domain unit (range default/max/inverted, SD boundary, labels for all 7 enum values); repository + use case + action unit; INTEGRATION on real Postgres as `systemfact_app` (seed movements of several tipos/dates/branches/empresas: only the session branch's rows appear, other branch and other empresa never, date window boundaries in SD, pagination total == count with filters, order, an Operador-style ctx is refused by the app guard); RTL for the table, filters, empty state, access message, no controls; e2e `inventario-historial` assertions added to the existing inventario e2e (Administrador sees rows produced by the seeded flow or by the adjust form, Operador/Despachador see the access message). No test may skip.
- S8 Version bump 0.30.0 (`app/package.json` + `.release-please-manifest.json` + `app/CHANGELOG.md`, UTF-8 no BOM), Conventional Commits, squash-merge with `Closes #N`; deploy only with the owner's explicit approval (read-only: smoke is enough).
