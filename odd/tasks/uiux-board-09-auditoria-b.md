## Specs

- S1 The audit table shows the user's `nombreUsuario` (it carries the `CODIGO-` prefix; legacy users may lack it) in the Usuario column, with the person's full `nombre` in the cell `title`; and the branch `nombre` in the Sucursal column (today's `Empresa` text stays for rows whose `sucursalId` is NULL). If a name cannot be resolved, fall back to today's `#<id>` so a row is never blank.
- S2 The names come from the SAME page query (Prisma relation select `usuario: { select: { nombreUsuario, nombre, activo } }` and `sucursal: { select: { nombre, activo } }`) executed INSIDE the existing widened-branch-GUC window of `consultarAuditoriaEnTx` (`app/src/modules/auditoria/infrastructure/consultar-auditoria.repository.ts`), so an admin pinned to branch A sees names of branch B in the same empresa and nothing outside the empresa. No N+1, no second query per row. Update the stale "no relations" comments there.
- S3 The Usuario and Sucursal filter inputs become `<select>`s (`Todos` / `Todas` first), fed by option lists read in the SAME transaction and the SAME widened window, behind the SAME admin gate (the role check in `http/actions.ts` and `ctx.esAdmin` in the use case run BEFORE any option query; a non-admin gets the existing refusal and NO option query runs). Users: new thin reader `listarUsuariosOpcionesEnTx(tx, ctx)` in the auditoria infrastructure (select ONLY `{ id, nombreUsuario, nombre, activo }`, pinned with `tenantWhere`/`empresaId`, no pagination but a hard cap of 500, order: active first then `nombreUsuario`). Branches: reuse `listarSucursalesAdministracion(ctx, tx)` (tenant use case, admin-gated, accepts the caller's `tx`) or an equivalent that returns `{ id, nombre, activa }` for active AND inactive branches. Inactive users/branches stay selectable (old rows reference them) and are labelled `(inactivo)` / `(inactiva)`. Option label for users: `<nombreUsuario> — <nombre>`.
- S4 Contract: the action returns `{ pagina, opciones: { usuarios, sucursales } }` from one transaction (DTO types in the domain module, no Prisma types leaking to the UI). The URL contract does NOT change: params stay `usuarioId` / `sucursalId`; pagination and every other filter keep working and are preserved across pages. A `usuarioId`/`sucursalId` present in the URL but missing from the option list (stale or foreign id) must not crash: render it as a fallback option `#<id>` (selected) so the filter stays visible and the table shows what the query returned (empty for a foreign id: RLS).
- S5 Security: only `nombreUsuario`, `nombre`, `activo` for users and `nombre`, `activa` for branches leave the server (never `email`, `passwordHash`, `authUserId`, `rol`, tokens). Admin-only, same empresa only. `valorAnterior`/`valorNuevo` stay hidden in the UI (slice C) and out of any new field. No authorization, RLS or migration change; no new dependency. The branch GUC is restored in `finally` exactly as today.
- S6 Tokens/a11y/touch from slice A stay: no raw palette, no `dark:`, `min-h-11` selects with visible `<label>` names (`Usuario`, `Sucursal`), guard test still green.
- S7 Tests: (a) RTL: names and fallbacks in the table, selects with `Todos`/`Todas`, inactive labels, fallback option for a URL id not in the list, URL/pagination preservation; (b) unit: the repository/use-case shape and the cap; (c) REAL-Postgres integration in `app/src/integration/auditoria-consulta.integration.test.ts` (extend; follow its fixture helpers): an admin of branch A sees names of users/branches of branch B of the same empresa in rows AND options; another empresa's names never appear in rows or options; an inactive user and an inactive branch are still labelled/listed; a non-admin is refused with `AUDITORIA_NO_AUTORIZADO` and gets no option data; after the read the branch GUC is the caller's again; the option list respects the 500 cap ordering (active first). These cannot be run locally (no Postgres): type-check and lint them, CI runs them. (d) update existing auditoria tests only where the new truth demands it, never weakening assertions; extend `app/e2e/auditoria.spec.ts` minimally if useful (admin sees the two selects), never breaking it.
- S8 Version bump 0.45.0 (parent: `app/package.json`, `.release-please-manifest.json`, `app/CHANGELOG.md`, bytes only, keep line endings).
